## 확정된 결정 (아직 `docs/adr.md`에 없음. 다음 세션에서 ADR로 옮길 것)

1. **스택**: React + Vite + TypeScript PWA. 서버 없이 정적 배포되고 해커톤 속도가 빠르다. Next.js는 서버 기능을 안 쓰므로 선택하지 않았다.
2. **목표 순서**: 1차는 웹앱의 완벽한 구현과 시연, 2차는 Expo Go 전환 검토. 이식을 쉽게 하는 규칙: 포인트·승인·마디 로직은 React 없이 순수 TypeScript로 분리, 스타일 방식은 하나로 통일, 카메라·소리·저장소 같은 웹 전용 기능은 함수 하나로 감싸기.
3. **서버**: 기기가 2대(아이 폰, 부모 폰)라서 Supabase(데이터베이스와 파일 저장소)를 쓴다. 가족 코드로 두 기기를 연결한다(가정).
4. **캐릭터 표현 방식**: 촬영 화면의 "지켜보는 칸"은 **영상**, 스테이지 길 홈과 축하·챕터 전환·상자 연출은 **전신 투명 이미지 + 코드 움직임**. Rive(부위별 움직임)는 시간이 남을 때 주인공 한 명으로 먼저 시험한다.
5. **촬영 화면 배치**: 위쪽에 펭귄(캐릭터) 칸, 아래쪽에 카메라. 사용자가 "펭귄을 위로"라고 요청해서 이 순서가 되었다.
6. **영상은 더 만들 예정** (사용자가 직접). 다른 캐릭터 영상도 같은 방식으로.
7. **스테이지 지도**는 듀오링고식 세로 길로 확정.

## 주의할 점

- **`git push`는 사람이 한다** (프로젝트 규칙, `.claude/settings.json`에서도 막음). 이번 세션의 커밋은 푸시 전이다.
- 파이썬은 `-I`(격리 모드) 대신 **`-P`**로 실행한다. `-I`는 사용자 영역에 설치된 Pillow를 가려서 "PIL이 없다"로 보인다.
- Codex로 이미지를 만들 때: 깃 저장소가 아닌 폴더에서는 `--skip-git-repo-check`가 필요하다. 백그라운드 알림의 "종료 코드 0"은 래퍼 명령의 것이라 믿지 말고 로그의 `CODEX_EXIT`와 결과 파일을 확인한다.
- 부품 시트 요청문에는 **크기 비율을 숫자로 적는다**(눈 흰자 폭 / 머리 폭: 미지정 54%, 지정 34%·24%). 적지 않으면 얼굴 부품이 1.9배 크게 나온다.
- `hero_look_idle.mp4`: 소리가 들어 있어 `muted`로 재생해야 한다. 처음과 끝 프레임이 이어지지 않아 반복 재생 때 튄다(유사도 0.87). 오른쪽 아래에 작은 별 모양 마크가 있어서, 시험에서는 영상 가로를 135%로 키워 가운데만 보이게 했다. 욕실 배경이 영상에 포함되어 있어 카메라 위에 겹치는 연출은 안 된다.
- 시험용 웹 페이지(위쪽 펭귄 영상, 아래쪽 카메라)는 임시 폴더에 있어서 **사라졌다**. 필요하면 다시 만든다: 영상 `muted playsinline loop autoplay`, `width: 135%; margin-left: -17.5%; object-fit: cover; object-position: 50% 0%`.
- 자동 시험 브라우저(Playwright)에는 카메라가 없어서 카메라 기능은 아직 검증하지 못했다.
- 터미널 입력창에서 Ctrl+C를 누르면 쓰던 글이 사라진다. 긴 설명은 메모장에서 쓰고 붙여 넣는다.
- 팀원에게 보낼 글은 파일이 아니라 **카톡에 복사하기 좋은 평문**으로 채팅에 쓴다(사용자 선호, 메모리에 저장됨).
- 프로젝트가 `/mnt/c`(윈도우 폴더)에 있어서 WSL에서 개발 서버를 띄우면 파일 감시가 느릴 수 있다. 하네스가 PowerShell 기반이라 윈도우 쪽 실행을 권한다.
- 이전 세션에서 사용자가 "웹앱 형태로 안 할 것"이라고 한 적이 있는데, 이번 세션에서는 "1차 목표는 웹앱"으로 정리됐다. 이유는 확인하지 못했다.
