# 결정 기록 (ADR)

새 결정은 맨 아래에 번호를 이어서 추가한다. 이전 결정을 뒤집을 때는 원래 항목을 지우지 말고 상태를 "대체됨 (ADR-0NN)"으로 바꾼 뒤 새 항목을 쓴다.

형식:

```
## ADR-0NN 제목
- 상태: 승인 | 대체됨 (ADR-0NN)
- 날짜: YYYY-MM-DD, 작성: (사람 이름 또는 Phase N 세션)
- 맥락: 왜 결정이 필요했나
- 결정: 무엇을 하기로 했나
- 대안: 검토했지만 고르지 않은 것과 이유
- 결과: 이 결정으로 생기는 제약과 할 일
```

## ADR-001 스택: React + Vite + TypeScript PWA
- 상태: 승인
- 날짜: 2026-10-31, 작성: 기획 세션
- 맥락: 해커톤 속도가 중요하다. 폰 1대 구조라서 서버 기능이 필요 없다 (ADR-003).
- 결정: React + Vite + TypeScript로 PWA(홈 화면에 설치하는 웹앱)를 만든다. 정적 파일로 배포한다.
- 대안
  - Next.js: 서버 기능(서버 렌더링, API)을 쓰지 않아서 고르지 않았다.
  - Expo(React Native)로 바로 시작: 웹에서 카메라, 영상, 화면 연출을 빠르게 반복해 시험하는 편이 시연 준비에 유리하다. 앱 전환은 2차로 검토한다 (ADR-002).
- 결과
  - 아이폰 Safari와 안드로이드 Chrome에서 카메라 권한, 영상 녹화·재생이 되는지 실기기로 시험해야 한다. (아직 검증하지 못함)
  - 새 런타임 의존성을 넣을 때는 이 문서에 이유를 남긴다.

## ADR-002 목표 순서와 이식 규칙
- 상태: 승인
- 날짜: 2026-10-31, 작성: 기획 세션
- 맥락: 1차 목표는 웹앱의 완벽한 구현과 시연이고, 2차로 Expo Go 앱 전환을 검토한다. 2차에서 다시 만들지 않도록 처음부터 나눠 둘 것이 있다.
- 결정: 아래 세 가지 규칙을 지킨다.
  1. 코인·단계·실패 같은 규칙 계산은 React 없이 순수 TypeScript로 분리한다.
  2. 스타일 방식은 하나로 통일한다.
  3. 카메라, 소리, 저장소 같은 웹 전용 기능은 함수 하나로 감싼다.
- 대안: 처음부터 웹과 앱 양쪽을 맞추는 구조(공용 UI 라이브러리). 해커톤 일정에 비해 무거워서 고르지 않았다.
- 결과: 규칙 로직은 화면과 따로 시험할 수 있다. 웹 전용 기능 호출이 화면 코드에 흩어지면 안 된다.

## ADR-003 폰 1대, 서버 없이 폰 안에 저장
- 상태: 승인 (저장소 종류는 시험 후 확정)
- 날짜: 2026-10-31, 작성: 기획 세션
- 맥락: 이전 기획은 아이 폰과 부모 폰 2대를 가족 코드로 연결하고 서버(Supabase)에 사진·영상을 올리는 구조였다. 하지만 5~8세 아이는 엄마 폰을 빌려서 쓰기 때문에 폰 1대를 나눠 쓰는 구조가 더 현실적이다.
- 결정: 폰 1대를 쓴다. 서버(Supabase)를 쓰지 않고, 단계·코인·선물·설정과 인증 사진·영상을 모두 폰 안의 브라우저 저장소에 저장한다. 저장소 종류는 IndexedDB(브라우저 안의 큰 데이터 저장소)를 쓸 예정이다.
- 대안
  - Supabase(서버와 파일 저장소): 폰이 1대라서 필요 없고, 계정 연결은 사람이 해야 한다.
  - localStorage: 용량이 작아 영상을 저장하기 어렵다.
- 결과
  - 브라우저 데이터를 지우면 기록이 모두 사라진다. 다른 폰으로 옮기거나 백업할 수 없다.
  - 사진·영상을 저장할 수 있는 용량 한계와 촬영 화질은 구현 전에 시험해야 한다. (아직 검증하지 못함)
  - 시연 직전에 앱을 처음 상태로 되돌리는 방법이 필요하다.
  - 저장소 접근은 함수 하나로 감싼다 (ADR-002).

## ADR-004 캐릭터 표현 방식
- 상태: 승인
- 날짜: 2026-10-31, 작성: 기획 세션
- 맥락: 듀오링고급의 생동감을 목표로 하지만 캐릭터는 정지 이미지와 짧은 영상으로 준비되어 있다.
- 결정
  - 촬영 화면의 "지켜보는 칸"은 **영상**(두리번거리는 펭귄)을 쓴다.
  - 길 홈, 클리어 기쁨, 코인 획득, 하강, 장 전환은 **전신 투명 이미지 + 코드 움직임**(이동, 확대, 흔들림)으로 만든다.
  - Rive(부위별로 움직이는 캐릭터 도구)는 시간이 남을 때 주인공 한 명으로 먼저 시험한다.
- 대안: 모든 연출을 영상으로 만들기. 만드는 비용이 크고 용량이 커서 고르지 않았다.
- 결과
  - 영상은 소리가 있어서 `muted`로 재생해야 한다. 반복 이음새가 튀는 문제는 구현 때 처리한다.
  - 연출별로 필요한 캐릭터 에셋(환호, 응원, 걷기, 쉼)을 더 준비해야 한다.

## ADR-005 촬영 화면 배치: 위에 펭귄, 아래에 카메라
- 상태: 승인
- 날짜: 2026-10-31, 작성: 기획 세션
- 맥락: 인증하는 동안 캐릭터가 "지켜본다"는 느낌을 줄 방법이 필요했다. 후보는 위아래 반반, 화면 위를 돌아다님, 촬영 순간에만 반응 3가지였다.
- 결정: 위쪽에 펭귄 영상 칸, 아래쪽에 카메라 화면을 둔다.
- 대안: 나머지 후보 둘. 영상 속 욕실 배경이 있어서 카메라 위에 겹치는 연출은 맞지 않고, 위아래 반반이 가장 단순하다.
- 결과: 위쪽 영상 가로를 135%로 키워 가운데만 보이게 하면 오른쪽 아래의 작은 별 마크가 가려진다.

## ADR-006 인증은 즉시 클리어, 부모는 사후에 실패만 돌린다
- 상태: 승인
- 날짜: 2026-10-31, 작성: 기획 세션
- 맥락: 이전 기획은 부모가 승인해야 확정되는 구조였다. 아이가 부모 확인을 기다려야 하고, 부모가 확인하지 않으면 진행이 멈춘다.
- 결정: 아이가 인증을 제출하면 바로 클리어되고 10코인을 받는다. 부모는 하고 싶을 때 인증을 한 건씩 보고 성공 또는 실패를 누른다. 실패하면 캐릭터가 한 단계 내려가고 코인 10을 회수한다.
- 대안: 부모가 승인해야 확정. 아이가 기다리게 되어 "즉시 칭찬"이라는 핵심과 맞지 않아 고르지 않았다.
- 결과
  - 부모가 반드시 확인한다는 전제다. 확인하지 않으면 가짜 인증도 그대로 남는다.
  - 코인이 마이너스가 될 수 있다 (`docs/prd.md` R-08, R-09).
  - 인증 데이터에 상태(클리어, 확정, 취소)가 필요하다.

## ADR-007 부모 영역은 같은 폰에서 PIN으로 나눈다
- 상태: 승인
- 날짜: 2026-10-31, 작성: 기획 세션
- 맥락: 아이와 부모가 폰 1대를 나눠 쓴다 (ADR-003). 아이가 부모 기능(인증 확인, 미션·선물 수정, 구독)에 들어가면 안 된다.
- 결정: 아래 탭을 홈 / 상점 / 부모 세 개로 두고, 부모 탭은 PIN 4자리를 입력해야 들어간다. 부모 탭에 다시 들어올 때는 PIN을 또 입력한다.
- 대안
  - 기기 역할(아이/부모)을 처음에 한 번 고정하는 방식: 폰이 1대라 의미가 없다.
  - 부모 입구를 숨기기(작은 자물쇠 등): 시연에서 부모 영역 전환이 한눈에 보이지 않는다.
- 결과: PIN 복구 기능은 이번 범위에 없다. PIN 틀림 횟수 제한도 두지 않는다 (가정). 아이가 추측해서 들어올 수 있다.

## ADR-008 결제는 화면만 만든다 (가짜 결제)
- 상태: 승인
- 날짜: 2026-10-31, 작성: 기획 세션
- 맥락: 수익 목표는 월 구독(미션 추가, 20단계 이후)이다. 이번 목표는 시연이다.
- 결정: 구독 안내 화면과 가짜 결제 화면만 만든다. 결제를 마치면 구독 상태가 켜지고 제한이 풀린다. 실제 결제는 붙이지 않는다. 가격은 정하지 않았다.
- 대안: 실제 결제 서비스 연동. 결제 서비스 계정 연결이 필요한데 이는 사람이 해야 하고, 시연 목적에는 필요하지 않다.
- 결과: 발표에서 "이렇게 결제를 만들 것"이라고 말로 설명한다. 2차 앱 전환 때는 인앱결제 정책을 다시 검토해야 한다.

## ADR-009 홈은 듀오링고식 세로 길, 하루 한 단계
- 상태: 승인
- 날짜: 2026-10-31, 작성: 기획 세션
- 맥락: "길 위를 올라가는 진행감"이 핵심이다. 이전 기획은 마디 10개 단위의 챕터와 보물상자였다.
- 결정: 홈은 듀오링고처럼 아래에서 위로 올라가는 세로 S자 길이다. 단계는 1~100이고 10단계가 1장이다. 하루에 한 단계씩 진행하고, 단계 안의 미션을 모두 깨야 다음 단계로 올라간다. 단계를 누르면 그날의 미션 목록이 뜬다.
- 대안: 이전의 마디와 보물상자 구조. 코인과 상점으로 대체되었다.
- 결과: 하루에 한 단계라서 시연은 1단계만 보여준다. 장 전환(C7)과 20단계 잠금은 이번에 만들지 않는다.

## ADR-010 지금 단계의 인증이 실패하면 캐릭터는 내려가지 않는다
- 상태: 승인 (가정, 사용자 확인 필요)
- 날짜: 2026-11-01, 작성: 구현 세션
- 맥락: R-08은 실패하면 "한 단계 내려간다"고 정한다. 그런데 한 단계에 미션이 여러 개일 때, 아직 다 깨지 못해 올라가지 않은 지금 단계의 인증이 실패할 수 있다. 이때 한 단계를 내리면 이미 다 깬 아래 단계에 서게 되어 다시 올라갈 방법이 없다.
- 결정: 실패한 인증의 단계가 지금 단계보다 아래일 때만 한 단계 내린다. 지금 단계의 인증이면 단계는 그대로 두고 그 미션을 "다시 해보자"로 바꾼다. 어느 경우든 코인 10은 회수하고 쉬는 상태("내일 만나자")를 풀어 바로 다시 할 수 있게 한다.
- 대안: 항상 한 단계 내리기. 위의 막힘이 생겨서 고르지 않았다.
- 결과: 시연(미션 1개, 1단계)에서는 항상 한 단계 내려가므로 시나리오와 같다. 한참 위에 있다가 예전 인증이 실패한 경우는 여전히 미정이고, 지금은 한 단계만 내린다.

## ADR-012 피그마 "펭귄 퀘스트" 디자인을 화면 스타일로 쓰고, 흐름은 문서를 따른다
- 상태: 승인
- 날짜: 2026-11-01, 작성: 구현 세션
- 맥락: 팀 피그마(Page 2)에는 완성 디자인이 있지만 화면 구성(AI 퀘스트 초안, 모험 탭 등)이 `docs/유저저니.md`와 다르다. 사용자는 "레이아웃(유저저니, 화면레이아웃.html) 기반으로 피그마 디자인을 넣어 달라"고 요청했다.
- 결정
  - 화면과 흐름은 `docs/유저저니.md` 6장(O1~O9, C1~C10, P1~P7)을 따른다.
  - 색, 둥근 카드, 아래로 그림자가 있는 입체 버튼, 코인 칩, 단계 발판 색, 아이 내비게이션 모양, 글꼴(Jua, Noto Sans KR)은 피그마에서 가져온다. 아이 영역은 하늘색과 파랑, 부모 영역은 피그마 부모 화면 v2의 연보라와 보라를 쓴다.
  - 파란 펭귄 포즈 3개(인사, 축하, 엄지)는 피그마의 투명 캐릭터 시트에서 잘라 `public/char/`에 둔다.
  - 글꼴은 Google Fonts에서 불러온다. 인터넷이 없으면 시스템 글꼴로 보인다.
- 대안: 피그마 화면 구성을 그대로 구현. PRD·유저저니와 흐름이 달라 고르지 않았다.
- 결과: 피그마의 글자 크기(8~13px)는 5~8세 아이에게 작아서 아이 화면은 더 크게 키웠다. 오프라인 시연이 필요하면 글꼴 파일을 `public/`에 넣어야 한다.

## ADR-013 아이 영역을 피그마 v3 디자인으로 바꾼다
- 상태: 승인
- 날짜: 2026-11-01, 작성: 구현 세션
- 맥락: 팀이 피그마 Page 2의 아이 영역을 새로 만들었다 ("02 · 아이 영역": 02A 채택 스테이지 UI, 02B 지도 원본 10장, 02F DAY 미션 카드, V3/C1~C10). 사용자가 이 디자인을 반영해 달라고 요청했다.
- 결정
  - 홈(C1)은 10개 장의 그림 지도를 위에서 아래로 이어 붙인다. 1일이 맨 위, 100일(마법성)이 맨 아래다. 발판 좌표, 발판 재질(얼음, 서리 바위, 눈 녹은 산길, 보랏빛 바위), 발자국, 말풍선, 장 이름은 피그마 값을 그대로 쓴다. 지도 그림은 `public/map/`에 있다.
  - 단계 팝업(C2)은 피그마 "미션 00N" DAY 카드 모양으로 바꾸고, 목록에는 그날의 미션과 상태를 넣는다.
  - 5일마다 반짝 별, 10일마다 챕터 보물 표시를 지도와 DAY 카드에 보여준다. 실제 보상(배지, 상자)은 아직 주지 않는다. 규칙이 정해지지 않았다.
  - 촬영, 클리어, 다시 해보자, 상점, 구매 팝업은 V3 화면(하늘색 바탕, 흰 카드, 왼쪽 정렬 Jua 제목)으로 바꾼다. 문구도 피그마를 따른다 ("코인이 부족합니다" → "코인이 조금 더 필요해").
  - 촬영 화면 위쪽은 피그마의 정지 이미지 대신 기존 펭귄 영상(ADR-005)을 유지한다.
  - 지도 아래 탭은 피그마 02A의 둥근 사각 아이콘 탭(홈 / 상점 / 부모)을 쓴다. 부모 영역은 바꾸지 않았다.
- 대안: 피그마 프로토타입처럼 "미션 완료" 버튼만으로 다음 발판으로 가기. 인증 필수(R-04)와 맞지 않아 고르지 않았다.
- 결과
  - O3 하강 연출은 지도 맨 아래(마법성)에서 1일까지 올라오는 스크롤이 됐다.
  - 지도 그림 10장은 피그마 아틀라스를 장별로 자른 저해상도(약 290×1080) 이미지라 큰 화면에서는 약간 흐리다. 원본 고해상도를 받으면 교체한다.

## ADR-014 온보딩 첫 미션은 연습으로 친다
- 상태: 승인
- 날짜: 2026-11-01, 작성: 구현 세션 (사용자 요청)
- 맥락: 온보딩 첫 미션(O8)을 1단계 클리어로 치면, 끝나자마자 2단계 "내일 만나자"가 되어 첫날에 아이가 할 수 있는 미션이 없다.
- 결정: 첫 미션은 연습 인증(`practice`, 0단계로 기록)이다. 클리어 연출과 +10코인은 그대로 주고 부모 확인 목록에도 쌓이지만, 단계를 올리지 않는다. 홈에서는 1일 발판에 서 있고 바로 1일 미션을 할 수 있다. 연습 인증이 실패하면 코인 10만 돌려받고 단계는 그대로다.
- 대안: 첫 미션을 1일 미션으로 치기(이전 방식). 첫날 더 할 게 없어 고르지 않았다.
- 결과: 시연에서 "실패하면 한 단계 내려온다"를 보이려면 1일 미션을 한 번 깨서 2일로 올라간 뒤 부모가 그 인증을 실패로 누른다. C8 화면의 "N단계 → N-1단계"는 실제로 내려갔을 때만 보인다.

## ADR-015 상점을 피그마 "상점 01~04" 가게 화면으로 바꾼다
- 상태: 승인
- 날짜: 2026-11-01, 작성: 구현 세션 (사용자 요청)
- 맥락: 팀이 피그마 Page 2에 새 상점 시안 네 장(어서 와!, 상품 둘러보기, 구매 완료, 크레딧 부족)을 만들었다. 사용자가 상점을 이 디자인으로 바꿔 달라고 요청했다.
- 결정
  - 상점은 나무 간판, 줄무늬 차양, 기둥, 계산대 뒤 펭귄 점원이 있는 가게 화면이다. 들어가면 01 인사 화면, "상품 구경하기"로 02 목록, 구매하면 03(윙크 펭귄), 코인이 모자라면 04(우는 펭귄)가 나온다.
  - 상점 화면에는 아래 탭을 두지 않는다. 시안대로 아래는 나무 마루이고, "‹ 모험으로"와 "모험하러 가기"로 홈에 돌아간다.
  - 피그마의 "크레딧"은 앱 전체 용어(규칙 문서, 홈 코인 칩, 클리어 연출 "+10 코인")에 맞춰 "코인"으로 쓴다.
  - 시안에는 없지만 구매 확인 팝업("이 선물을 살까?")은 남긴다. 누르자마자 코인이 빠지면 아이가 실수로 살 수 있다 (유저저니 C10).
  - 윙크·울음 펭귄 그림은 피그마에서 받아 `public/char/hero_wink.png`, `hero_cry.png`로 둔다. 인사 펭귄은 기존 `hero_wave.png`와 같은 그림이다.
- 결과: 상점 테스트 흐름에 "상품 구경하기"(shop-browse)와 "모험으로"(shop-back)가 한 단계씩 늘었다.

## ADR-016 앱 이름을 "빙하루"로 정하고 부모 설정 온보딩(O4~O7)을 피그마로 바꾼다
- 상태: 승인
- 날짜: 2026-11-01, 작성: 구현 세션 (사용자 요청)
- 맥락: 피그마 Page 2의 온보딩 시안(V3/O1~O9)이 앱 이름을 "빙하루"로 쓰고, 부모 설정 화면이 말풍선과 새 펭귄 그림으로 정리돼 있다. 사용자가 이름을 "빙하루"로 바꾸고 부모 설정 화면만 이 디자인으로 바꿔 달라고 했다.
- 결정
  - 앱 이름은 "빙하루"다 (시작 화면 로고, 홈 머리글, 탭 제목, PWA 이름, 구독 안내 제목). 이전 임시 이름 "펭귄 모험"은 쓰지 않는다.
  - O4 부모 호출, O5 PIN, O6 이름, O7 미션 고르기는 피그마처럼 흰 바탕, 말풍선, 말풍선 아래 파란 펭귄, 아래 고정 파란 버튼, 위쪽 파란 진행바로 바꾼다. 스타일은 `src/ob.css`에 모으고 `.ob` 안에서만 적용해 다른 화면에 영향이 없게 한다.
  - 펭귄 그림은 `assets/character/hero/generated/onboarding/`의 새 그림 3장(o4, o6, o7)을 높이 480px로 줄여 `public/char/onb_*.png`로 둔다. 원본은 장당 약 1MB라 그대로 쓰면 앱이 무거워진다.
  - 시작(O1), 인사, 소개 영상(O2), 첫 미션(O8), 성공(O9)은 바꾸지 않는다. 소개 영상 `intro.mp4`는 그대로 쓴다.
  - 촬영 화면(C3)의 펭귄 영상(ADR-005)은 유지하되, 말풍선을 영상 칸 위로 옮기고 칸을 키워 머리 깃털부터 가슴까지 보이게 한다. 영상 자체가 상반신이라 전신은 나오지 않는다.
  - 홈의 코인 칩은 상점과 같은 금색 알약에 금색 동전 모양으로 바꾼다.
- 대안: 온보딩 전체(O1~O9)를 한 번에 바꾸기. 마음에 안 들 때 되돌릴 범위가 커서 부모 설정 화면만 먼저 바꿨다.
- 결과
  - 화면 문구가 바뀌었다 (O4 "이제 부모님을 불러줘!", O5 "네 자리 번호를 정해 주세요.", O7 버튼 "이 미션으로 시작"). 자동 점검(e2e)은 요소 이름으로 찾으므로 영향이 없다.
  - 피그마의 뒤로가기 "‹"는 넣지 않았다. 기존에도 이 화면들에 뒤로가기가 없고, 넣으면 PIN과 이름 입력 상태를 어떻게 다룰지 정해야 한다.
  - 미션 목록의 그림은 기존 이모지를 그대로 쓴다. 피그마처럼 펭귄 그림으로 바꾸려면 `hero_onboarding_mission_*.png` 5장을 줄여 쓰면 된다.
  - 이 문서 외에 `docs/화면레이아웃.html`(옛 레이아웃 참고 자료)의 이름은 바꾸지 않았다.
- 추가 (2026-11-01): 계산대 장면(어서 와 / 구매 완료 / 코인 부족)은 스크롤하지 않는다. 화면이 낮으면 장면 전체를 같은 비율로 줄여 버튼까지 한 화면에 담는다. 지도의 장과 장 사이에는 흐릿한 구름 띠를 덮어 그림이 끊겨 보이지 않게 한다.
