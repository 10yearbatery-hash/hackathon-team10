# 개발 계획

- 작업 단위는 Phase다. 한 Phase는 `claude -p` 세션 하나가 처음부터 끝까지 맡는다.
- Phase 안의 작업 순서는 세션이 정한다. 이 문서는 목표와 범위만, `plan/acceptance.json`은 완료 기준만 정한다.
- Phase 완료 = 그 Phase의 수용 기준이 모두 `passes: true` + 검증 명령 통과 + 리뷰 `VERDICT: PASS`.
- 진행 상태는 `plan/acceptance.json`, `progress/handoff.md`, `progress/reviews/phase-N.md`에서 본다. 이 문서에는 상태를 적지 않는다.
- 실행 방법은 `harness/README.md`.

마감이 가까워 시연 범위 전체를 Phase 1 하나로 만들었다. Phase 2는 실기기 확인과 다듬기다.

---

## Phase 1. 시연 범위 전체

- **목표**: 서비스기획 15장의 시연 시나리오 1~9를 폰 한 대로 끊김 없이 보여줄 수 있다.
- **범위**: PRD의 필수 기능 전부 (F-01~F-04, F-10~F-13, F-20~F-27, F-30~F-36). 화면은 유저저니 6장, 스타일은 피그마 (ADR-012).
- **범위 밖**: F-28 장 전환, F-37 20단계 잠금, 실제 결제, 음성 안내.
- **끝나면**: `npm run verify` 통과, 시연 시나리오 e2e 통과, 주요 화면 스크린샷 확인.
- **메모**: 카메라는 가짜 카메라로만 시험했다.

## Phase 2. 실기기 확인과 다듬기

- **목표**: 아이폰 Safari와 안드로이드 Chrome에서 시연이 끝까지 된다.
- **범위**: 카메라 권한·녹화·재생 확인과 수정, 배포(HTTPS), 영상 반복 이음새, 효과음 다듬기, 오프라인 글꼴.
- **범위 밖**: 새 기능.
- **끝나면**: 실기기 두 대에서 시연 시나리오를 끝까지 해 본 기록이 `progress/log.md`에 있다.
- **메모**: 배포와 실기기 확인은 사람이 해야 한다.
